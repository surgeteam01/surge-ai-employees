# Module 4: Keeping it current

**Purpose:** A brain written once and never touched drifts from the business it describes, and every skill reading it drifts with it. This module is for later — the second, fifth and twentieth time the file is opened.

## What goes stale, and how fast

- **Current context and boundaries** goes stale first — goals, challenges, green lights. It is written for the next three to six months. Re-read it **quarterly**: open the file, go through that part, and ask "still true?" for each answer. Rewrite what has moved; leave the rest.
- **Offers and expertise** moves when a price changes, an offer is added or retired, or something is newly out of scope. Update it the day the change happens, not at the next quarter.
- **Business identity**, **Brand voice and style**, **Brand assets** are slow. Touch them when the business repositions or rebrands — or when a skill hands back something better than what is there.

## When another skill hands something back

Several skills end by producing facts the brain should keep:

- `find-your-niche` → who the business serves and what makes it different.
- `write-like-a-human` → the whole voice part, from real samples.
- `nail-your-pricing` and `productize-your-service` → the offers, with prices.
- `build-your-own-brand-identity` → colours, typefaces, imagery, design don'ts.
- `audit-my-business` → current goals and current challenges.

When one of them hands back brain lines, **fold them into the existing file under the matching key** — replace the old answer, do not append a second one. Read the replaced answer back so the founder sees what changed. On the Claude website, hand back the *whole* updated file, since a partial paste leaves two versions.

## How to update, mechanically

1. Read the file (Module 3 says where).
2. Say which keys will change and show the old and new answer side by side.
3. Write the file once, whole, in Module 1's shape.
4. Say where you wrote it.

Never edit by memory of a previous session: read the file as it is now, because the founder may have edited it by hand since.

## When to re-run the full interview

Rarely. A new business, a pivot large enough that the identity part is wrong, or a founder who wants to start over. Otherwise the interview is the exception and the update is the rule.

## Handoff

None — this module closes the loop. The next time any skill in the pack opens, it reads the file as it stands.
