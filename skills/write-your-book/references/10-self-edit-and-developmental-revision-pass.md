# Module 10: Self-Edit & Developmental Revision Pass

**Purpose:** A structural edit — pacing, redundancy, chapter flow, promise delivery — before front/back matter and assembly, catching what's fixable at the manuscript level rather than getting lost in line-level wordsmithing too early.

## Process

1. **Check each chapter delivers the promise stated in its Module 5 outline** — if it doesn't, that's a structural gap, not a style issue.
2. **Check for redundancy across chapters** — the same point made three separate times usually means it belongs in one chapter, with the others trimmed or cross-referenced.
3. **Check pacing** — a chapter that drags relative to its target length, or a section dense enough that it actually needed to be split into two chapters.
4. **Verify the throughline holds** — does the whole manuscript still trace back to Module 2's core premise, start to finish, or has it drifted?
5. **Note line-edit issues** (word choice, sentence-level clarity) without rabbit-holing into fixing them at this stage — that's a later, separate pass.

## Output format

```
CHAPTER-BY-CHAPTER REVISION NOTES
Ch. [N]: [promise delivered? redundancy? pacing issue?] → [fix]
(repeat per chapter)

THROUGHLINE CHECK: [holds / drifted — where]

BEFORE/AFTER SUMMARY: [what changed at the structural level]
```

## Handoff

Feeds Module 13 with revised chapters. Apply the fixes to the actual chapter drafts from Module 8 before assembling — this module produces the notes, but the manuscript that reaches Module 13 should already reflect them.
