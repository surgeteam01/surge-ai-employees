# Module 13: Full Webinar Funnel Assembler

**Purpose:** Assemble every prior module's output into one cohesive, ready-to-run webinar funnel — the registration page, the reminder sequence, the full live script, and both post-event follow-up sequences — so the pipeline's output is something the user can actually schedule and deliver.

## Process

1. **Follow the map from Module 4** as the skeleton, dropping each piece into place: the registration page (Module 5), the reminder sequence (Module 6), the full webinar script (Modules 7, 8, 9, 10, 11 combined into one continuous script), and the two post-webinar sequences (Module 12).
2. **Assemble the webinar script as one continuous document** — the open, content sections with proof woven in, the transition, and the full pitch through close — so the presenter has a single script to rehearse from rather than scattered fragments.
3. **Smooth transitions throughout** — between reminder touchpoints, between content sections, and especially at the content-to-pitch handoff — the whole funnel should read/sound like one coherent voice, not several modules stitched together.
4. **Check voice consistency** against the brief from Module 1 throughout, particularly between the written pieces (registration page, emails) and the spoken script, which should feel like the same presenter throughout.
5. **Check pacing on the script specifically** — mark approximate timings per section against Module 4's allocation, and flag if the assembled script runs long against the target length.
6. **Verify nothing was lost**: registration page, reminder sequence, full script (open through close), Q&A prep, and both follow-up sequences should all be present.

## Output format

```
=== REGISTRATION PAGE ===
[from Module 5]

=== REMINDER SEQUENCE ===
[from Module 6, with timing]

=== WEBINAR SCRIPT (full, continuous) ===
[Open → Content Sections → Transition → Pitch → Close → Q&A prep, assembled from Modules 7-11]

=== POST-WEBINAR FOLLOW-UP ===
Attendee-No-Buy Sequence: [from Module 12]
No-Show Sequence: [from Module 12]
```

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass almost always has at least one weak transition, an underused proof point, or a script that runs long against its time budget.
