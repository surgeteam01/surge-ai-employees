# Module 9: Internal Linking & Site Architecture Designer

**Purpose:** Design how pages link to each other — internal linking distributes authority across a site and helps search engines understand which pages matter most and how topics relate, a factor entirely within the site owner's control unlike backlinks from other sites.

## Process

1. **Identify a logical site architecture** — group related pages/clusters (from Module 4) into topic clusters with a clear "pillar" page (a comprehensive overview) linking out to more specific supporting pages, and those supporting pages linking back to the pillar — this structure signals topical authority to search engines more effectively than isolated, unconnected pages.
2. **Recommend specific internal links within each page's content** (from Module 8) — natural, contextual links to genuinely related pages, using descriptive anchor text (not generic "click here") that itself carries some keyword-relevance signal.
3. **Identify orphaned or under-linked pages** in Module 1's existing content inventory — pages with few or no internal links pointing to them are both harder for search engines to discover/value and harder for users to find.
4. **Recommend a reasonable internal linking density** — enough to build genuine topical connections, not so many that links feel forced or spammy within the content.

## Output format

```
SITE ARCHITECTURE:
Pillar page: [topic] → Supporting pages: [list, with link relationships]
(repeat per topic cluster)

INTERNAL LINK RECOMMENDATIONS (per page from Module 8):
[Page] → links to: [related page] — anchor text: [descriptive, natural]
(repeat)

ORPHANED/UNDER-LINKED PAGES FLAGGED: [from Module 1's existing content inventory]
```

## Handoff

Feeds Module 13's assembly as both a content-level instruction (which links to add where) and a site-structure recommendation.
