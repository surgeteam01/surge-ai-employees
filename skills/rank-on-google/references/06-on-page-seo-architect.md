# Module 6: On-Page SEO Architect

**Purpose:** Design the technical on-page architecture per target page — title tag, meta description, header structure, and URL slug — the foundational technical layer every page needs, regardless of how strong the content itself is.

## Process

1. **Assign primary and secondary keyword targets per page** from Module 4's clusters — one page per cluster, not one page per individual keyword.
2. **Design the header structure (H1-H3)** — one H1 matching the primary keyword/intent closely, H2s covering the major sub-topics (informed by Module 5's gap analysis and Module 3's question bank), and H3s for further breakdown where needed. This structure should mirror a logical outline a reader would actually want, not just a keyword-stuffed list of headers.
3. **Design the URL slug** — short, descriptive, keyword-relevant, and stable (avoid slugs that would need to change later, which breaks existing links/authority).
4. **Note any technical basics relevant to the CMS/platform** (from Module 1): mobile responsiveness, page load speed considerations, and proper heading hierarchy (only one H1 per page) — flagged as implementation requirements, not rewritten in full technical detail here.

## Output format

```
PAGE: [target cluster/topic]
PRIMARY KEYWORD: [x] — SECONDARY KEYWORDS: [list]
URL SLUG: [proposed slug]

HEADER STRUCTURE:
H1: [...]
H2: [...] (repeat per major sub-topic from Module 5's gaps and Module 3's questions)
  H3: [...] (where further breakdown is needed)

TECHNICAL BASICS FLAG: [any platform-specific considerations from Module 1]
```

## Handoff

Feeds Module 7 (title/meta written to match this structure) and Module 8 (content is written to fill this header outline).
