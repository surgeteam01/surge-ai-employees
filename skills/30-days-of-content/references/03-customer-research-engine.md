# Module 3: Customer Research Engine

**Purpose:** Build a Voice-of-Customer (VoC) profile — the real pains, desires, objections, and exact phrases the audience uses — so content topics come from what the audience actually cares about, not what the business finds interesting to talk about.

## Process

1. **Pull from real material first**, if any exists: comments on past content, reviews, support questions, sales conversations. Ask the user if any of this exists before generating from scratch.
2. **If no real material exists**, build a hypothesis-based profile and label it clearly as a hypothesis, recommending validation against real engagement once the first batch of content goes out.
3. **Identify the buyer awareness stage**, since it shapes the pillar mix in Module 4 — an unaware/problem-aware audience needs more educational, problem-naming content; a more aware audience can handle more direct, solution-focused and proof-based content.
4. **Extract exact phrases** the audience uses — these directly feed Module 6 (headlines/hooks) and Module 8 (content ideas), since content written in the audience's own language performs meaningfully better than content in generic industry-speak.
5. **Identify recurring questions** the audience asks — these are often the single best source of concrete, specific content ideas, more reliable than brainstorming topics from scratch.

## Output format

```
AWARENESS STAGE: [one of the five, with justification]

TOP PAINS (ranked): [...]
TOP DESIRES (ranked): [...]
RECURRING QUESTIONS: [specific questions the audience actually asks]
EXACT-PHRASE BANK: [words the audience actually uses]

CONFIDENCE: [Real data / Hypothesis — recommend validation]
```

## Handoff

Awareness stage shapes Module 4's pillar mix. Recurring questions and the phrase bank feed Module 8's idea generation directly — many of the 30 ideas should be direct answers to real questions from this list, not invented from scratch.
