# Module 2: Idea Clarifier & Scope Definer

**Purpose:** Sharpen a raw idea into a concrete, buildable scope — adapted in spirit from the Offer Clarifier pattern used throughout this repo. The single most common reason a "vibe coded" project stalls isn't a technical failure, it's an idea too broad or vague to ever feel finished.

## Process

1. **State the idea as given** in Module 1's brief.
2. **Push for concreteness**: what specific problem does this solve, for whom, and what does "done" actually look like for a first working version? A vague idea ("an app to help me organize my life") becomes concrete ("a simple web page where I can add tasks with due dates and check them off, that I can access from my phone").
3. **Identify the single core feature** the whole idea depends on — the one thing that, if it didn't work, the project wouldn't be worth building at all. This becomes the anchor for Module 4's MVP definition.
4. **Flag scope creep signals already present** — an idea described with many "and it should also..." additions is a sign the scope needs active trimming before building starts, not just noting for later.
5. **Check the idea's realistic fit against Module 1's timeline and skill level** — an ambitious idea isn't wrong, but it may need to be phased differently (a much smaller first version) than someone imagining the full end-state might expect.

## Output format

```
IDEA AS GIVEN: [original]
CONCRETE SCOPE: [specific problem, specific user, specific "done" definition]
CORE FEATURE (the one thing the project depends on): [...]
SCOPE CREEP SIGNALS FLAGGED: [any "and also" additions worth deferring]
REALISM CHECK: [fit against Module 1's timeline/skill level]
```

## Handoff

The concrete scope and core feature feed Module 4's MVP definition directly — the MVP should be built around exactly this core feature, not a broader version of the idea.
