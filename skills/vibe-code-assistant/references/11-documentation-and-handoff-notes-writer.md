# Module 11: Documentation & Handoff Notes Writer

**Purpose:** Write lightweight documentation so future-you (returning to this project in three months) or a future collaborator can understand it — a lightweight but real requirement, not a formality, since "vibe coded" projects without any notes are notoriously hard to pick back up.

## Process

1. **Write a short README-style summary**: what the project does, the tech stack (Module 3), how to run it locally, and how it's deployed (Module 10).
2. **Note any non-obvious decisions** — a workaround, a specific reason a particular approach was chosen over an obvious alternative — since these are exactly the things a future reader (including future-you) would otherwise have to re-derive from scratch.
3. **Keep it genuinely short** — a documentation effort that becomes its own large project defeats the purpose; a page or less for an MVP-scale project is usually enough.
4. **List the backlog (from Module 4)** in this document too, so future work has a ready starting point rather than requiring a fresh scoping exercise.

## Output format

```
PROJECT README:
What it does: [one paragraph]
Tech stack: [from Module 3]
How to run locally: [steps]
How it's deployed: [from Module 10]
Non-obvious decisions: [brief notes]
Backlog (next features): [from Module 4]
```
