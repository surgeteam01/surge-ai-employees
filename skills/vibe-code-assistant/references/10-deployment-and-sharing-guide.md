# Module 10: Deployment & Sharing Guide

**Purpose:** Get the finished MVP actually live and in front of real users — a project that stays on a local machine forever never gets tested against reality, and this is a step many first-time builders don't know how to take.

## Process

1. **Recommend a specific deployment path matched to Module 3's chosen stack** — a specific, beginner-friendly hosting platform appropriate to the tech choice, favoring options with the simplest possible deployment process (often a few clicks or a single command) over more powerful but more complex options that aren't needed for an MVP's scale.
2. **If this environment has a `run` skill available, reference it directly** for actually launching/screenshotting the app locally before deployment, rather than re-deriving that guidance here.
3. **Walk through the deployment steps at a level matched to Module 1's skill level** — specific enough to actually follow, not just "deploy it to [platform]" without the intermediate steps.
4. **Recommend a simple way to share the finished link** with the intended first users (per Module 2's "who this is for"), and a simple way to collect their reactions (feeds Module 12).

## Output format

```
DEPLOYMENT PATH: [specific platform] — reason: [simplicity fit for MVP scale + Module 3's stack]
DEPLOYMENT STEPS: [walked through at Module 1's skill level]
SHARING PLAN: [how to get the link to first intended users]
```

## Handoff

Feeds Module 12's feedback loop — the shared link is what real feedback starts flowing from.
