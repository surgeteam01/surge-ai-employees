# Module 12: Iteration & Feedback Loop Designer

**Purpose:** Design how to gather real feedback after launch and use it to prioritize what to build next — an MVP's job is to be tested against reality, and this module makes sure that actually happens rather than the project ending at deployment.

## Process

1. **Design a simple feedback collection method** matched to Module 10's sharing plan — a direct conversation with the first few users, a simple feedback form, or just watching how they actually use it, chosen for simplicity over building an elaborate feedback system that itself becomes a distraction.
2. **Define what to listen for**: confusion points (where a user hesitates or asks "how do I..."), requests that reveal a real unmet need, and anything that breaks in real usage that wasn't caught in Module 8's testing.
3. **Re-prioritize Module 4's backlog based on real feedback** rather than the plan made before any real user touched the product — real usage almost always reveals priorities different from what seemed important in planning.
4. **Recommend a realistic next-iteration cadence** — small, frequent updates based on real feedback rather than disappearing to build a large "version 2" in isolation.

## Output format

```
FEEDBACK COLLECTION METHOD: [conversation / simple form / usage observation] — reason: [simplicity fit]
WHAT TO LISTEN FOR: [confusion points, real unmet needs, real-world breakage]
BACKLOG RE-PRIORITIZATION APPROACH: [how real feedback should reorder Module 4's list]
NEXT-ITERATION CADENCE: [recommended rhythm for small, frequent updates]
```

## Handoff

Feeds Module 13's assembly as the plan's final, forward-looking section.
