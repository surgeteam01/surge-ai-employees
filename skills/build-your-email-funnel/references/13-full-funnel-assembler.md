# Module 13: Full Funnel Assembler

**Purpose:** Assemble every prior module's output into one cohesive, fully-triggered email funnel — this is where the pipeline stops being a set of parts and becomes a single deliverable the user can load straight into their ESP.

## Process

1. **Follow the map from Module 4** as the skeleton, dropping each sequence's emails (from Modules 6, 7, 10, 11) into place in send order, each paired with its subject line and preview text from Module 5.
2. **Insert CTAs and closing lines from Module 12** into each email, and insert any woven (non-dedicated) objection lines from Module 9 at their noted placement.
3. **Smooth transitions between sequences** — the funnel should read as one relationship written by one sender, not four stitched-together sequences. Rewrite connecting lines where sequences meet (the last Welcome email should set up the first Nurture email's arrival; the last Nurture email should set up the Sales sequence's opening; etc.), reusing the closing lines from Module 12 as the bridge.
4. **Check voice consistency** against the brief from Module 1 throughout — flag and fix any email that drifted in tone, particularly across sequences written by different modules.
5. **Attach trigger and timing metadata to every email**, not just narrative order — each email needs its entry trigger or send-delay (from Module 4), so the output can be handed directly to whoever builds the automation in the ESP.
6. **Verify nothing was lost**: every sequence in Module 4's map should be present, the offer stack, proof, guarantee, objections, pricing, and CTAs should all appear where planned, and no email should be missing its subject line.

## Output format

Produce the full funnel as one continuous document, organized by sequence and email, in send order:

```
SEQUENCE: [name]

EMAIL [n] — Trigger/Timing: [entry event or delay from prior email]
Subject: [subject line]
Preview text: [preheader]
Body: [full email copy, with CTA included]

(repeat per email, per sequence, in send order)
```

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass almost always has at least one weak transition, one underused proof point, or a deliverability risk worth catching before the funnel goes live.
