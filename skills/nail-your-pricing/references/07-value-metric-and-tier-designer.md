# Module 7: Value Metric & Tier Designer

**Purpose:** Choose what the price actually scales with (the value metric) and, if the pricing model calls for it, design the tier structure — this is where a single flat number becomes a real pricing architecture that matches how different segments extract different value.

## Process

1. **Choose the value metric** — the thing the price is denominated against: per-seat, per-outcome/result, flat regardless of usage, per-project-scope, or per-unit-of-consumption. The right metric is one that scales roughly in step with the value the buyer receives — charging per-seat for something that delivers value regardless of team size, for instance, misaligns price with value and creates resentment or churn.
2. **Decide if tiers are warranted** (only if Module 4's model called for tiering). Tiers make sense when genuinely different segments exist with genuinely different needs/budgets — not just as an arbitrary way to have "more options." A single well-priced option is often better than an unjustified 3-tier split.
3. **If tiering, design 2-3 tiers** (good/better/best is the most common, reliable structure): differentiate by real value drivers (access level, support level, usage caps, outcome scope) rather than arbitrary feature-gating that frustrates buyers. Design the middle tier deliberately as the one most buyers should land on — it should look like the obvious best value relative to both neighbors.
4. **Name tiers meaningfully** (tied to the outcome or segment, not just "Basic/Pro/Enterprise" by default, unless that convention genuinely fits the market) and make the differentiation scannable in one glance.

## Output format

```
VALUE METRIC: [chosen metric] — reason: [why it scales with delivered value]

TIER STRUCTURE: [single option / tiered] — reason: [segment justification, or why a single option is better here]

(if tiered)
[Tier 1 name] — for: [segment] — includes: [key differentiators]
[Tier 2 name — "recommended"] — for: [segment] — includes: [key differentiators]
[Tier 3 name] — for: [segment] — includes: [key differentiators]
```

## Handoff

This structure is what Module 8 actually attaches numbers to — the price point calculation happens per tier if tiered, or once if a single option. Module 12 (Presentation Writer) uses the tier names and differentiators directly rather than re-deriving them.
