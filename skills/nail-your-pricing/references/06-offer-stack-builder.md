# Module 6: Offer Stack Builder

**Purpose:** Present the offer as a value-anchored stack — every component named, valued, and justified — rather than a flat description. Stacking makes the eventual price feel small relative to what's included, and gives Module 8 real components to weigh when setting the number.

## Process

1. **List every component** of the offer: the core deliverable, plus any bonuses, templates, community access, support, guarantees-as-value, etc.
2. **Assign an honest perceived value to each component.** This should be defensible (what would this cost or sell for on its own?), not inflated to the point of being unbelievable — an implausible inflated stack undermines trust rather than building it, and undermines the pricing strategy's credibility specifically.
3. **Order components by weight** — the core offer first and biggest, bonuses supporting it, not overshadowing it.
4. **Total the stack** as a reference point Module 8 will set the actual price against, so the gap between value and price does the persuading.
5. **Write one line of justification per component** — what it does for the buyer, not just what it is.

## Output format

```
OFFER STACK:
- [Core offer] — Value: $[x] — [one line: what it delivers]
- [Bonus 1] — Value: $[x] — [one line]
- [Bonus 2] — Value: $[x] — [one line]
...
TOTAL VALUE: $[sum]
```

## Handoff

This stack feeds directly into Module 7 (Value Metric & Tier Designer, if tiers are in scope) and Module 8 (Price Point Calculator uses the total value as one anchor among several, not the sole input) and Module 12 (Presentation Writer decides how and where to present it — all at once vs. revealed progressively).
