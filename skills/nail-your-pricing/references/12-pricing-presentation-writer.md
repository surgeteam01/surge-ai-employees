# Module 12: Pricing Presentation Writer

**Purpose:** Write the actual copy that presents the price — anchoring, framing, tier presentation, and the call to action — so the number lands as justified rather than arbitrary, wherever it's shown (a pricing page, a proposal, a sales deck, a quote email).

## Process

1. **Anchor before revealing the price**, using the value stack from Module 6 (total value vs. actual price) so the price lands as a discount against value, not a cost in isolation.
2. **Present tier structure clearly if tiered** (from Module 7): the middle/recommended tier should be visually or verbally emphasized, with a one-line reason it's the best fit for most buyers — never leave the buyer to guess which option is "for them."
3. **Write one justification line per price** tied back to the transformation (Module 2), not just the deliverables — buyers pay for outcomes, not features.
4. **Present payment options clearly** (from Module 11) directly alongside the price, not buried in fine print or revealed only later.
5. **Place the guarantee (Module 10) immediately beside or under the price** — risk-reversal works best presented in the same breath as the ask, not as an afterthought elsewhere on the page.
6. **Write the CTA** — state the next step plainly ("Start with the [tier name] plan" beats "Buy Now"), and pre-empt the single strongest objection from Module 9 directly in the surrounding copy if there's room to do so naturally.

## Output format

```
PRICING PRESENTATION:

ANCHOR LINE: [value stack recap → price reveal]

PRICE PRESENTATION:
[Tier/option name] — $[price] — [what's included, one line] — [payment options]
(repeat per tier if applicable, with the recommended tier flagged)

JUSTIFICATION LINE: [ties price to transformation]

GUARANTEE: [from Module 10, placed directly alongside]

OBJECTION PRE-EMPT (if room): [strongest objection, addressed briefly in-line]

CTA: [specific next-step copy]
```

## Handoff

This is the copy Module 13 assembles into the final deliverable (a standalone pricing page/sheet, or slotted into a proposal/sales deck format depending on how the user actually presents pricing). Module 14 will test whether this presentation is strong enough or needs an A/B variant.
