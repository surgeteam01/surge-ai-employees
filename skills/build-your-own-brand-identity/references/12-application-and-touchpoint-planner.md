# Module 12: Application & Touchpoint Planner

**Purpose:** Plan how the identity actually applies across the real touchpoints a customer will first encounter — a brand identity that only exists as an isolated logo and color swatches is unfinished; its real test is looking coherent applied to a website, a social profile, and physical/digital materials.

## Process

1. **List the priority touchpoints** given Module 1's business type: website (header, favicon), social media profiles (profile image, cover image, post templates), business card/stationery if relevant, product packaging if relevant, email signature, and any industry-specific touchpoint (e.g. a menu for a restaurant, a storefront sign for a physical location).
2. **Describe how the identity applies to each touchpoint** — which logo variation (from Module 9) fits which space, how the color palette and typography translate to that specific medium's constraints (a favicon needs the icon-only mark at a tiny size; a social cover image has specific dimension constraints).
3. **Flag any touchpoint where the identity as designed doesn't translate well** (e.g. a highly detailed logo that becomes illegible at favicon size) and recommend the specific variation or simplification needed.
4. **Prioritize touchpoints by what the user will actually need first**, given Module 1's business stage, rather than producing an exhaustive list of touchpoints irrelevant to their current situation.

## Output format

```
PRIORITY TOUCHPOINTS: [ranked by what's needed first, given Module 1's business stage]

APPLICATION PER TOUCHPOINT:
[Touchpoint] — logo variation used: [x] — specific application notes: [...]
(repeat per touchpoint)

TRANSLATION ISSUES FLAGGED: [any touchpoint where the identity needs a specific simplification/variation to work]
```

## Handoff

Feeds Module 13's assembly as the practical "how to actually use this" section of the guidelines.
