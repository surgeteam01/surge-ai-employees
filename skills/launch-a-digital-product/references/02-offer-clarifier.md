# Module 2: Offer Clarifier

**Purpose:** Sharpen the offer and the transformation it delivers before any launch content gets written. Every piece of a launch — the pre-launch content, the sales page, the cart-open emails — depends on a clear, specific transformation; a vague one produces a launch that feels busy but unfocused.

## Process

1. **State the current offer in one sentence**, as the user described it.
2. **Stress-test it against the Value Equation**: Dream Outcome (how big/specific is the result?), Likelihood of Success (how believable is it?), Time Delay (how fast do they get there?), Effort & Sacrifice (how easy is it?). Flag whichever of these four is weakest or missing.
3. **Rewrite the offer as a before → after transformation**, not a feature list. Bad: "a course with 40 video lessons." Good: "go from not knowing where to start with [skill] to a finished, portfolio-ready project in 6 weeks, following along at your own pace."
4. **Check specificity.** Push for numbers, timeframes, and named outcomes wherever honestly possible.
5. **Flag anything unprovable or overclaimed** — this will surface again at Module 6's sales page objection-handling and, worse, as a refund driver in Module 11 if buyers feel misled once they're inside the product.

## Output format

```
CURRENT OFFER (as given): [one sentence]
WEAKEST LINK: [Dream Outcome / Likelihood / Time / Effort]
SHARPENED OFFER (one sentence): [rewrite]
TRANSFORMATION STATEMENT (one paragraph, before → after): [rewrite]
RED FLAGS: [anything overclaimed, vague, or unprovable]
```

## Handoff

The sharpened offer and transformation statement become the backbone of Module 4 (Launch Architect), Module 5 (Pre-Launch Content), and get passed directly into the Stage 6 handoff to `sales-page-that-converts` so that skill's own Offer Clarifier stage doesn't need to re-run from scratch. If the user pushes back on the sharpened version, ask which specific part felt wrong and refine.
