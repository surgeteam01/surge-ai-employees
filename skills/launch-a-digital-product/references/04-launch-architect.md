# Module 4: Launch Architect

**Purpose:** Produce the full launch timeline and model before any content gets written — this is the skeleton every other stage fills in, and the one place where the live-vs-evergreen decision and the cart-open/cart-close dates get locked down.

## Process

1. **Confirm the launch model** from Module 1's brief: a *live launch* (a real, publicly communicated cart-open and cart-close window — the highest-urgency, highest-effort model), an *evergreen launch* (always-on, each new lead runs their own personal timeline via automation), or a *hybrid* (launched live once, then converted to evergreen afterward — see Module 12).
2. **Set the pre-launch length** based on Module 3's awareness stage and list warmth from Module 1: colder/less-aware audiences need a longer pre-launch content run (e.g. 3 pieces of content over 1-2 weeks) to build belief; warm, highly aware audiences can run a compressed pre-launch (a single announcement piece) or skip straight to cart-open.
3. **Set cart-open duration** — typical live launches run the cart open for 5-7 days; shorter windows increase urgency but reduce the chance of catching everyone at the right moment, longer windows dilute urgency. Base the choice on list size and sales cycle length for the price point (a high-ticket offer often needs a longer window to accommodate sales calls or more deliberation).
4. **Map the full timeline** with every piece and its owning module: pre-launch content dates → cart-open date/sales page live → cart-open sequence dates → cart-close date/final urgency → post-purchase delivery trigger → (if hybrid) evergreen transition date.
5. **Decide if affiliates are in scope** (from Module 1) and, if so, when their enablement kit (Module 10) needs to be delivered to them — typically well before cart-open, so partners have time to plan their own promotion.
6. **Note which modules feed which piece**, including the explicit Stage 6 handoff to `sales-page-that-converts`, so nothing gets built twice.

## Output format

```
LAUNCH MODEL: [live / evergreen / hybrid] — reason: [list warmth + awareness stage + business goal]

TIMELINE:
Pre-launch content — dates: [x] — fed by: Module 5
Sales page live — date: [x] — fed by: Module 6 (handoff to sales-page-that-converts)
Cart open — date: [x] — cart-open sequence fed by: Module 7
Cart close — date: [x] — urgency sequence fed by: Module 8
Fast-action bonus window (if used) — date: [x] — fed by: Module 9
Affiliate kit delivery (if in scope) — date: [x] — fed by: Module 10
Post-purchase delivery — trigger: [purchase event] — fed by: Module 11
Evergreen transition (if hybrid) — date: [x] — fed by: Module 12

AFFILIATES IN SCOPE: [yes/no]
```

## Handoff

This timeline is the skeleton Module 13 (Assembler) will fill in. Every piece must map to exactly one upstream module's output — if a piece doesn't have a clear source, flag it now rather than discovering the gap once dates are already public.
