# Module 3: Customer Research Engine

**Purpose:** Build a Voice-of-Customer (VoC) profile — the real pains, desires, objections, and exact phrases clients use, plus what they typically ask to customize — so the package is designed and sold in the client's language, not the business's.

## Process

1. **Pull from real material first**, if any exists: past client conversations, project retros, proposals that were accepted vs. rejected, or client emails asking for changes/additions. Ask the user if any of this exists before generating from scratch.
2. **If no real material exists**, build a hypothesis-based VoC profile from the audience description and general market knowledge — label it clearly as a hypothesis and recommend validating the eventual package against the first few real client conversations.
3. **Identify what clients most commonly ask to customize or add** — this is distinct from generic pain/desire research and directly informs Module 4's scope boundary: recurring requests are candidates for inclusion in the standard package (or a clearly-priced add-on), while rare one-off requests are candidates for explicit exclusion.
4. **Identify the buyer's decision criteria** — price, speed, done-for-them simplicity, ongoing relationship/support — since this shapes how the package should be tiered (Module 6) and positioned (Module 5).
5. **Extract exact phrases** clients use to describe their situation and what they want — these feed Module 12's presentation copy.

## Output format

```
TOP PAINS (ranked):
1. ...
2. ...
3. ...

TOP DESIRES (ranked):
1. ...
2. ...
3. ...

COMMON CUSTOMIZATION REQUESTS: [list — candidates for standard inclusion or priced add-on]

DECISION CRITERIA (ranked): [price / speed / simplicity / ongoing support / other]

EXACT-PHRASE BANK: [words clients actually use]

CONFIDENCE: [Real data / Hypothesis — recommend validation]
```

## Handoff

Common customization requests feed directly into Module 4's scope decisions. Decision criteria feed Module 5 (positioning) and Module 6 (tier design — e.g. if speed is the top criterion, a "rush" tier makes sense). The phrase bank feeds Module 12.
