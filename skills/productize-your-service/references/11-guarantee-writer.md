# Module 11: Guarantee Writer

**Purpose:** Write an ethical, confidence-building guarantee that reduces the buyer's perceived risk in trying a fixed-scope package instead of a custom-quoted engagement — reused directly from `sales-page-that-converts`, since the underlying guarantee-design logic is identical.

## Process

1. **Confirm what the business can actually stand behind**, checked against Module 8's delivery SOP specifically — a guarantee that assumes delivery quality the SOP hasn't actually verified yet (e.g. on a brand-new package with no track record) should be more conservative than one backed by proven delivery.
2. **Choose a guarantee type that fits a productized service**: **unconditional** (money-back within a window) works well for lower-risk, lower-price packages; **conditional** (a defined revision/fix commitment if the deliverable doesn't meet the stated scope) often fits service packages better than a blanket refund, since it reinforces the scope boundary rather than undermining it; **performance-based** only if the transformation is genuinely measurable and reliably achievable within the fixed scope.
3. **Write the guarantee in plain, warm language**, and make sure it doesn't quietly promise unlimited revisions or scope flexibility that contradicts Module 4's boundary — a guarantee that accidentally reopens the scope question defeats the purpose of productizing in the first place.

## Output format

```
GUARANTEE TYPE: [chosen type] — reason: [fit with package, price point, and delivery confidence]
GUARANTEE COPY: [2-4 sentences, ready to place alongside the package]
FINE PRINT (if needed): [any necessary conditions, written plainly, consistent with Module 4's scope boundary]
```

## Handoff

This feeds Module 12 (typically placed directly beside each package) and doubles as a rebuttal to the price/trust objections surfaced in Module 10.
