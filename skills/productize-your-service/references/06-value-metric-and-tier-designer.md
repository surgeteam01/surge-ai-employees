# Module 6: Value Metric & Tier Designer

**Purpose:** Design the package tier structure — reused directly from `nail-your-pricing`, adapted here to the classic productized-service pattern of 2-3 fixed packages (often literally named Basic/Standard/Premium or similarly), each a genuinely different scope, not just a different price for the same thing.

## Process

1. **Choose the value metric** — most productized services price per-engagement or per-cadence-period (monthly retainer) rather than per-seat or per-usage; confirm this matches Module 5's chosen model.
2. **Design 2-3 tiers** differentiated by real scope differences from Module 4 — not arbitrary feature-gating. A common, reliable pattern: a base tier matching the core "always included" scope, a middle tier adding the most commonly requested standard inclusions (designed to be the one most clients pick), and a top tier adding priced add-ons, faster turnaround, or more hands-on involvement (calls, revisions, priority support).
3. **Make the differentiation genuinely valuable at each step up** — a common failure mode is a top tier that's just "the same thing, faster," which can feel like paying more for less patience rather than more value; ensure each tier up adds something the client would recognize as more, not just less friction.
4. **Name tiers meaningfully** — tied to the outcome or client segment where that fits the brand voice, rather than defaulting to generic "Basic/Pro/Enterprise" labels that read as software-pricing conventions transplanted onto a service.

## Output format

```
VALUE METRIC: [per-engagement / per-month retainer / other] — confirmed against Module 5's model

TIER STRUCTURE:
[Tier 1 name] — scope: [from Module 4's "always included"] — for: [client segment/situation]
[Tier 2 name — "recommended"] — scope: [adds most-requested standard inclusions] — for: [client segment/situation]
[Tier 3 name] — scope: [adds add-ons/turnaround/hands-on involvement] — for: [client segment/situation]
```

## Handoff

This structure is what Module 7 attaches actual numbers to, and what Module 8's delivery SOP must be built to support consistently across every tier — a tier that looks good on paper but can't actually be delivered at the promised turnaround for every client who buys it is a scope-creep risk in disguise.
