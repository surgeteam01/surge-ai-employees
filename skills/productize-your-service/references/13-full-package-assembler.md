# Module 13: Full Package Assembler

**Purpose:** Assemble every prior module's output into one cohesive, ready-to-use package — the client-facing package page/sheet, plus the internal delivery SOP that makes it actually deliverable — so the pipeline's output is something the user can publish and start selling against immediately.

## Process

1. **Assemble the client-facing package** first: the presentation copy from Module 12, incorporating the tier comparison, proof, objection pre-empts, and guarantee.
2. **Assemble the internal companion document**: the scope boundary and offer stack from Module 4, the full delivery SOP from Module 8, and the objection/FAQ reference from Module 10 — this is what the business (or a future hire) actually operates from day to day, separate from what the client sees.
3. **Check consistency** between the two documents — the scope, turnaround, and price promised publicly must match exactly what the internal SOP is actually built to deliver; a mismatch here is exactly the kind of gap that causes scope creep or broken promises down the line.
4. **Check voice consistency** against the brief from Module 1 throughout the client-facing package.
5. **Verify nothing was lost**: all tiers, the guarantee, proof, and CTA should be present in the client-facing package, and every step of the delivery process (intake through handoff) should be present in the internal SOP.

## Output format

```
=== CLIENT-FACING PACKAGE PAGE (publish or send directly) ===
[Full assembled presentation from Module 12]

=== INTERNAL DELIVERY DOCUMENT (operations use) ===
SCOPE BOUNDARY & OFFER STACK: [from Module 4]
DELIVERY SOP: [from Module 8]
OBJECTION/FAQ REFERENCE: [from Module 10]
```

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass can still carry a scope/price mismatch or a delivery SOP that looks fine on paper but hasn't been stress-tested against real capacity.
