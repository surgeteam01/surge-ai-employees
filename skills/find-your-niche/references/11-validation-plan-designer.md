# Module 11: Validation Plan Designer

**Purpose:** Design concrete, low-cost steps to test the chosen niche and positioning against real market response before the user fully commits — everything up to this point has been research and analysis; this module is where the pipeline insists on contact with reality.

## Process

1. **Design a small number of specific, low-cost validation actions**, matched to the beachhead from Module 9: direct conversations (5-10 real conversations with people in the beachhead segment, testing whether the positioning statement from Module 7 actually lands and whether the pain is as described), a small test offer (a low-commitment paid or free pilot with a handful of beachhead prospects), content tests (publishing content aimed squarely at the beachhead and measuring genuine engagement, not just vanity metrics), or a landing page test (using `sales-page-that-converts` to build a simple page testing the positioning statement's pull before building a full offer).
2. **Define what a genuine positive signal looks like versus a false one** — e.g. polite interest in conversations isn't the same as someone taking a real action (booking a call, pre-paying, sharing contact info); design the validation steps to produce evidence of real commitment, not just agreeable conversation.
3. **Set a short timeframe and a small number of data points needed** before revisiting the decision — validation should be fast and cheap, not an excuse to delay committing indefinitely; recommend a specific number of conversations/signups/responses and a specific date to review results.
4. **Define what happens on a negative signal** — which alternate candidate segment from Module 4/6 to revisit first if the chosen niche doesn't validate, so a negative result has an immediate next step rather than leaving the user stuck.

## Output format

```
VALIDATION ACTIONS:
1. [Action — e.g. "5 real conversations with beachhead prospects"] — genuine positive signal: [what counts as real vs. polite interest]
2. [Action] — genuine positive signal: [...]
(repeat, typically 2-3 actions)

TIMEFRAME: [x weeks] — DATA POINTS NEEDED BEFORE REVIEW: [specific number]

IF NEGATIVE SIGNAL: [which alternate candidate segment to revisit, and why it's the next-best option]
```

## Handoff

This plan is the practical next step the user actually executes after this pipeline finishes — Module 13 includes it in the final assembled brief as an action plan, not just a strategic document to file away.
