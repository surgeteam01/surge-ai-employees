# Module 10: Objection Handler

**Purpose:** Address the objections and fears that come with niching down itself — reused in spirit from `sales-page-that-converts`'s Objection Handler, but aimed at a different audience entirely: not the niche's future customers, but the user themselves, who often needs to work through their own resistance to narrowing before they'll actually commit to and use the positioning this pipeline produces.

## Process

1. **Surface the common fears around niching down** and answer each directly and honestly, without false reassurance: "won't I lose clients outside this niche by narrowing?" (a sharper message that resonates deeply with a specific segment usually outperforms a vague message that mildly applies to everyone — and nothing stops taking a good-fit client outside the stated niche when they show up anyway), "what if I pick the wrong niche?" (this is exactly why Module 9's beachhead and Module 11's validation plan exist — the commitment is to a testable hypothesis, not an irreversible, permanent choice), "isn't this limiting?" (a strong niche is a starting position, not a permanent cage — expansion paths exist, per Module 9).
2. **Address the specific version of these fears surfaced by the user during this conversation**, if any came up earlier in the process, rather than only working from the generic list.
3. **Write these rebuttals in a direct, reassuring, but honest tone** — the goal isn't to talk the user out of legitimate caution, it's to make sure the caution is calibrated to the real risk (which this pipeline has already worked to reduce via research and scoring) rather than an unexamined general fear of commitment.

## Output format

```
OBJECTIONS TO NICHING DOWN (addressed):
1. [Fear] → [Direct, honest rebuttal]
2. ...

USER-SPECIFIC CONCERNS RAISED EARLIER (if any): [addressed directly]
```

## Handoff

This module is typically most useful right before Module 13's final assembly, when the user is about to commit to a specific written positioning statement — timing it here, rather than earlier, means the reassurance lands right when the decision is actually being made.
