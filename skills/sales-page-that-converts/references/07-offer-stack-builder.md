# Module 7: Offer Stack Builder

**Purpose:** Present the offer as a value-anchored stack — every component named, valued, and justified — rather than a flat description. Stacking makes the price feel small relative to what's included.

## Process

1. **List every component** of the offer: the core deliverable, plus any bonuses, templates, community access, support, guarantees-as-value, etc.
2. **Assign an honest perceived value to each component.** This should be defensible (what would this cost or sell for on its own?), not inflated to the point of being unbelievable — an implausible "$4,997 value" stack undermines trust rather than building it.
3. **Order components by weight** — the core offer first and biggest, bonuses supporting it, not overshadowing it.
4. **Total the stack** and set it against the actual price, so the gap does the persuading.
5. **Write one line of justification per component** — what it does for the buyer, not just what it is.

## This module feeds four separate blueprint blocks

The stack is not one section on the page. In `00-page-blueprint.md` it is spread across blocks 3, 7, 8, 9 and 10, and each one has a different job. Produce all five, or the assembler will have to invent the missing ones.

**Block 3 — the end-state promise.** "By the end of [the programme], you will have…" and then **five** specific outcomes. Not five features: five things that are *true about the buyer's life* afterwards, each with a line on why it matters and what it looks like. Five is the count; three reads thin against a considered price.

**Block 7 — What's Inside.** One card per module/phase, each with:
- the module title (name the transformation, not the topic — "Module 3: Your First Paying Client", not "Module 3: Sales")
- a few lines of benefit-driven description of the **mini-transformation** that module produces
- a "Module Highlights:" line followed by **3 bullets** of what is actually in there

The description sells the outcome; the bullets prove the volume. A card with only bullets reads as a syllabus, and a card with only prose reads as vague.

**Block 8 — the enrolment recap.** The offer name with its value, the module count, a recap of the result they get after implementing all of it, then the specific wins — and every win answers *what does this make possible?* rather than restating the deliverable. This block is where a reader who skipped block 7 catches up.

**Block 9 — bonuses.** "Plus These Bonuses to Help You [benefit of the bonuses]". Per bonus: title, a 1–2 sentence promise of the *result*, its value, then "What You'll Get:" + 3 bullets. Bonuses attach to a specific friction the core offer leaves behind — a bonus that duplicates the core offer adds a line to the stack and nothing to the decision.

**Block 10 — the value stack.** Every line item with its dollar value, then **Total Value: $X**, then the price reveal line. This is the only place the totals appear.

## Output format

```
END-STATE PROMISE (block 3) — "By the end of [X], you will have…"
1. [outcome] — why it matters: [...] — what it looks like: [...]
   (×5)

WHAT'S INSIDE (block 7)
Module 1: [transformation-named title]
  Description: [benefit-driven, the mini-transformation]
  Highlights: [bullet] / [bullet] / [bullet]
  (repeat per module)

ENROLMENT RECAP (block 8)
[Offer] (A $[x] Value) — [n] modules
Results recap: [...]
Win 1: [...] → what this makes possible: [...]
  (×3)

BONUSES (block 9)
"Plus These Bonuses to Help You [benefit]"
Bonus 1: [title] — [1-2 sentence result promise] — (A $[x] Value)
  What You'll Get: [bullet] / [bullet] / [bullet]
  (repeat per bonus)

VALUE STACK (block 10)
- [Core offer] — Value: $[x] — [one line: what it delivers]
- [Bonus 1] — Value: $[x] — [one line]
- [Bonus 2] — Value: $[x] — [one line]
...
TOTAL VALUE: $[sum]
ACTUAL PRICE: $[price]
FRAMING LINE: [one sentence tying the gap to the offer's core promise]
```

## Handoff

Blocks 3, 7, 8 and 9 go to Module 13 for placement as written. The value stack feeds Module 11 (Pricing Section Designer), which owns the price reveal directly under it, and Module 12 (CTA) for how the stack is referenced in the close and in FAQ slot 6.
