# Module 13: Full Page Assembler

**Purpose:** Assemble every prior module's output into one cohesive, consistent sales page — this is where the pipeline stops being a set of parts and becomes a single readable page.

## Process

1. **Follow the outline from Module 4** as the skeleton — which is the blueprint order from `00-page-blueprint.md`, minus whatever Module 4 recorded as a deviation. Drop each prior module's output into its assigned block. Do not re-order blocks here: the order was decided with the awareness stage in hand, and re-sequencing at assembly time quietly discards that decision.
2. **Smooth transitions between sections** — the page should read as one voice written in one sitting, not 13 stitched-together fragments. Rewrite connecting sentences where sections meet.
3. **Check voice consistency** against the brief from Module 1 throughout — flag and fix any section that drifted in tone.
4. **Check pacing** — long-form pages need rhythm breaks (short punchy lines, subheads, occasional single-sentence paragraphs) so they don't read as a wall of text.
5. **Verify nothing was lost**: offer stack, proof, objections, guarantee, pricing, and CTA should all be present and in the right order per the outline.
6. **Run the blueprint checklist below** before presenting anything. Every item on it is something that has been silently dropped from a page built this way.

## Blueprint checklist

- [ ] **Hero is three stacked lines** — outcome / timeframe / without three pains. Not one headline.
- [ ] **Qualifier block names three identities** and lands three head-nods in the buyer's own words.
- [ ] **End-state promise has five outcomes**, each with why it matters and what it looks like.
- [ ] **The CTA block appears four times** (blocks 5, 10, 13, 16) plus the header bar — or the outline recorded a deviation saying why. Fewer than two is always wrong.
- [ ] **The CTA block is identical at every placement**; only the line above it changes.
- [ ] **Every module/phase card has both** a benefit-driven description *and* three highlight bullets.
- [ ] **Total Value and the price sit adjacent**, with nothing between them.
- [ ] **Every stacked component has a value** and the values sum to the stated total. Add them up.
- [ ] **The guarantee is named** and states the length, the actions, the tangible + emotional benefits, and the exact refund process.
- [ ] **FAQ follows the six-slot order**, extras after slot 6, and slot 6 hands into CTA block #3.
- [ ] **Guarantee wording in FAQ slot 5 matches Module 10 verbatim** — not a paraphrase.
- [ ] **"Limited time" language appears only if a real deadline exists.** If not, it is rewritten, not left in.
- [ ] **Vocabulary column is consistent end to end** — one of enrol / get started / start trial / apply, and one of module / phase / feature / session. Search the draft for the other columns' words.
- [ ] **No placeholder survived.** Any `[bracketed]` text, `Lorem ipsum`, or `$XX` left in the draft is a bug, not a prompt for the user.
- [ ] **`NEEDS INPUT` blocks are listed to the user** rather than filled with invented testimonials, values, or founder story.

## Output format

Produce the full page as one continuous markdown document, with clear section headers matching the Module 4 outline, ready for the user to review end to end. Follow it with the completed blueprint checklist, and list anything still marked `NEEDS INPUT`.

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass almost always has at least one weak transition or underused proof point.
