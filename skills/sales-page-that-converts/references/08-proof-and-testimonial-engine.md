# Module 8: Proof & Testimonial Engine

**Purpose:** Turn raw results and rough testimonials into persuasive, specific proof blocks. Vague praise ("great course, loved it!") does almost nothing — specific, outcome-focused proof does the heavy lifting.

## Process

1. **Categorize available proof** into types: results/case studies (numbers, before-after), social proof (volume — "1,200 people have..."), authority proof (credentials, media, notable clients), and peer proof (testimonials from people like the reader).
2. **For each raw testimonial, extract the specific outcome** buried inside it. Rewrite for clarity and impact without inventing anything — never fabricate a result, number, or quote that wasn't given. If a testimonial is vague, either ask the user for the specific result behind it or use it only as supporting color, not as headline proof.
3. **Match proof type to placement**: authority/social proof near the top (builds initial trust), specific case-study proof near the offer stack (reduces purchase risk), peer testimonials near objections (answers "will this work for someone like me?").
4. **Write proof in more than one length**: a one-line pull-quote version and a fuller 2-4 sentence version, so Module 13 can choose based on the section.

## Output format

```
PROOF BLOCKS:

[Type: Result/Authority/Social/Peer]
Short: "[one-line version]"
Full: "[2-4 sentence version]"
Best placement: [section name]

(repeat per proof piece)

GAPS: [what proof is missing that would strengthen the page — flag for the user to go collect]
```

## Handoff

If "none yet" was the answer in Module 1, say so plainly here rather than inventing placeholder testimonials — recommend a first proof strategy instead (e.g. a beta cohort, a founder's-story-as-proof angle, or a money-back guarantee to substitute for missing social proof in Module 10).
