# Module 10: Executive Summary & Reporting Format Designer

**Purpose:** Structure the final report for its actual audience (from Module 1) — the same set of findings needs a different presentation for a technical co-founder than for a non-technical board member, and getting this wrong undermines even a rigorous analysis.

## Process

1. **Lead with the answer, not the methodology** — an executive summary states the direct answer to the question (Module 9) and the top 2-3 insights immediately, with supporting detail and methodology available after, not buried findings at the end of a long methodological walkthrough.
2. **Match depth and technicality to Module 1's audience** — a technical audience can handle the full methodology and caveats up front; a non-technical audience needs the plain-language insight first, with technical detail available as an appendix rather than blocking the main point.
3. **Design the report's section structure**: executive summary, key findings (from Module 9), supporting visualizations (Module 8), methodology/caveats (for readers who want it), and recommendations (Module 12).
4. **Keep the executive summary itself short** — a page or less, regardless of how much underlying analysis supports it; the summary's job is to be read completely, not to showcase the full depth of work.

## Output format

```
REPORT STRUCTURE (matched to Module 1's audience):
1. Executive Summary: [direct answer + top insights, kept short]
2. Key Findings: [from Module 9]
3. Supporting Visuals: [from Module 8]
4. Methodology & Caveats: [depth matched to audience technicality]
5. Recommendations: [from Module 12]

AUDIENCE-FIT NOTE: [how depth/technicality was calibrated to Module 1's stated audience]
```

Feeds Module 13's assembly as the report's actual structure.
