# Module 8: Data Visualization & Dashboard Designer

**Purpose:** Design the specific charts/visuals that best tell the story Module 6/7 found — this module decides *which* chart types fit the data and the finding; **for the actual execution (color, accessibility, chart construction), load the `dataviz` skill rather than improvising** — it has validated, accessible design guidance this module should defer to, not duplicate.

## Process

1. **Match chart type to the finding**: a time-series line chart for trends over time, a bar chart for comparing discrete categories/segments, a stacked bar or waterfall chart for showing how components contribute to a total change (useful for Module 6's quantified driver contributions), and a simple table when precision matters more than visual pattern.
2. **Avoid chart types that obscure the finding** — a pie chart for more than a few categories, a 3D chart that distorts perception, or any chart type chosen for visual interest rather than clarity.
3. **Design for the audience from Module 1** — a technical audience can handle more density and nuance; a non-technical executive audience needs fewer charts, each making one clear point.
4. **When it's time to actually build the chart(s)**, invoke the `dataviz` skill for the color palette, accessibility, and construction guidance rather than reinventing that work here.

## Output format

```
CHARTS NEEDED:
[Finding, from Module 6/7] → Chart type: [x] → Reason: [why this type fits the finding] → Audience fit: [density/complexity appropriate to Module 1's audience]
(repeat per chart)

EXECUTION NOTE: [confirm dataviz skill will be loaded for actual chart construction/styling]
```

## Handoff

Feeds Module 10's report structure (charts get placed where they support the narrative) and Module 13's assembly.
