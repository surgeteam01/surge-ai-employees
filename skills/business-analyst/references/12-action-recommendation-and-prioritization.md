# Module 12: Action Recommendation & Prioritization

**Purpose:** Translate the synthesized insights into prioritized, concrete recommendations — an analysis that stops at "here's what happened" without a "here's what to do about it" leaves the actual decision-making work undone.

## Process

1. **For each key insight (Module 9), propose a specific action** — concrete enough to actually assign to someone, not a vague direction ("improve retention" is not actionable; "add a specific onboarding email at day 3, targeting the segment identified as highest-churn-risk" is).
2. **Prioritize recommendations** by a combination of expected impact (tied to Module 6's quantified findings where available) and implementation difficulty/cost — a high-impact, low-effort recommendation should rank above a marginal, expensive one.
3. **Note what would need to be true for each recommendation to work**, and any risk or dependency — recommendations should be presented with enough honesty about uncertainty that the stakeholder can make an informed call, not oversold as guaranteed fixes.
4. **Recommend a way to measure whether each action actually worked** — a specific metric (already defined in Module 4) and a timeframe to check back, so recommendations lead to a feedback loop rather than a one-time report.

## Output format

```
RECOMMENDATIONS (prioritized):
1. [Specific action] — tied to insight: [from Module 9] — expected impact: [x] — effort: [x] — how to measure success: [metric + timeframe]
2. ...

RISKS/DEPENDENCIES: [what would need to be true for top recommendations to work]
```

## Handoff

Feeds Module 13's assembly as the report's final, action-oriented section.
