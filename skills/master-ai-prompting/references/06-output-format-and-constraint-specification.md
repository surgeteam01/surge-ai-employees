# Module 6: Output Format & Constraint Specification

**Purpose:** Teach how to specify exactly the format and structure wanted — one of the highest-leverage, most commonly skipped techniques, since an unspecified format defaults to whatever the AI guesses is generically appropriate, which is rarely exactly what's needed.

## Process

1. **Teach specifying structure explicitly**: length (a rough word/paragraph count, not just "keep it short"), format (a list, a table, prose, a specific template with labeled sections), and any structural constraint (must include X, must exclude Y, must follow a specific order).
2. **Teach providing an explicit template when the format matters a lot** — literally showing the labeled structure wanted (as this repo's own skill modules do with their "Output format" sections) produces far more reliable results than describing the format in prose.
3. **Teach the difference between a constraint and a suggestion** — "try to keep it under 200 words" is a suggestion the AI may not honor strictly; "keep it under 200 words" stated as a hard constraint, especially reinforced by asking for a word count check, is more reliably followed.
4. **Apply to Module 2's real use case** — what specific format/constraint was missing from the user's actual prompt that would have prevented the described output gap.

## Output format

```
FORMAT SPECIFICATION TECHNIQUES: [explicit length, explicit structure/template, explicit inclusions/exclusions]
CONSTRAINT VS. SUGGESTION: [explanation + example]
APPLIED TO USER'S REAL USE CASE: [specific format/constraint that was missing]
```
