# Module 13: Full Course Assembler

**Purpose:** Assemble every prior module's output into one cohesive, ready-to-build course package — the curriculum, the launch materials, and the student success system — so the pipeline's output is something the user can actually start producing content against and launching from.

## Process

1. **Assemble the curriculum-facing package**: the module/lesson structure from Module 4, filled in with the lesson-level content outlines from Module 5 — this is the production brief for actually recording/writing the course content.
2. **Assemble the launch package**: carried forward wholesale from Module 6's handoff to `launch-a-digital-product`.
3. **Assemble the operations package**: the student success and completion system from Module 12, alongside the guarantee's engagement conditions (Module 11) if applicable.
4. **Check consistency across all three**: the price and tier structure quoted in the launch package must match Module 10 exactly; the completion-objection rebuttal in the launch package's objection handling must match the actual system designed in Module 12, not a generic promise.
5. **Verify nothing was lost**: every module/lesson from Module 4 should have its outline present, the full launch package should be complete, and the completion system should cover onboarding, ongoing accountability, and re-engagement.

## Output format

```
=== CURRICULUM (production brief) ===
[Full module/lesson structure from Module 4, filled in with Module 5's outlines]

=== LAUNCH PACKAGE ===
[from Module 6's handoff to launch-a-digital-product]

=== STUDENT SUCCESS & OPERATIONS ===
[from Module 12, plus guarantee engagement conditions from Module 11 if applicable]
```

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass can still carry a mismatch between what the launch promises and what the completion system actually delivers.
