# Module 13: Full Sequence Assembler

**Purpose:** Assemble every prior module's output into one cohesive, fully-triggered outreach sequence — this is where the pipeline stops being a set of parts and becomes a single deliverable the user (or their sales rep, or their outreach tool) can execute from directly.

## Process

1. **Follow the map from Module 5** as the skeleton, dropping each touch's channel-specific copy (from Module 10, sourced from Modules 6/7/12) into place in send order.
2. **Insert CTAs from Module 11** into each touch, matched to the right position.
3. **Smooth transitions between touches** — the sequence should read as one coherent outreach from one sender, each touch aware of what came before it (referencing "following up on my note last week" naturally rather than restarting cold every time).
4. **Check voice consistency** against the brief from Module 1 throughout, particularly across touches and channels that were adapted separately in Module 10.
5. **Attach trigger, timing, and channel metadata to every touch** — each one needs its send delay/trigger and channel (from Module 5), so the output can be loaded directly into whatever outreach tool or CRM the user is using, or executed manually by a sales rep.
6. **Attach the objection reply playbook (Module 9) as a companion reference**, not as part of the outbound sequence itself, since it's used reactively once a reply arrives.
7. **Verify nothing was lost**: every touch in Module 5's map should be present with its channel-appropriate copy, the breakup touch should be included, and no touch should be missing its CTA.

## Output format

```
OUTREACH SEQUENCE — [Channel mix summary]

TOUCH [n] — Channel: [x] — Timing: [trigger/delay]
Subject (if email): [subject line]
Body: [full message copy, with CTA included]

(repeat per touch, in send order, ending with the breakup touch)

COMPANION: OBJECTION REPLY PLAYBOOK
[from Module 9, attached as reference]
```

## Handoff

This draft goes straight to Module 14 for scoring and optimization — don't present this as final without running it through the optimizer, since a first assembly pass almost always has at least one touch that reads too salesy too early, a missed compliance element, or a weak transition between touches.
